YuRandomTeleport 安装部署 ​

环境要求 ​

项目要求
JavaJava 8 及以上。源码以 sourceCompatibility = JavaVersion.VERSION_1_8 构建。
服务端Bukkit、Spigot、Paper、Purpur、Folia，以及 Mohist、Arclight、Youer 等兼容 Bukkit API 的混合端。
Minecraft目标适配 1.8.x-1.26.x。源码使用 Spigot API 1.8-R0.1-SNAPSHOT 编译，并通过反射读取新版世界高度。建议在正式服同版本测试后上线。
经济扣费可选。需要 Vault 与一个 Vault 经济服务提供者，例如 EssentialsX Economy、CMI 或其他经济插件。
PlaceholderAPI可选。安装后可启用 %yurtp_*% 状态、冷却、统计与最近位置变量。
网络访问bStats 统计会尝试访问统计服务；不影响核心随机传送功能。

兼容卖点 ​

YuRandomTeleport 的核心定位不是只服务某一个新版本，而是尽量覆盖从老版本生存服到新版本混合端的随机传送需求。

兼容范围说明
Minecraft 版本目标适配 1.8.x-1.26.x。
Bukkit 系服务端Spigot、Paper、Paper 衍生端。
混合端Mohist、Arclight、Youer 等 Bukkit API 混合端。
世界高度旧版本使用传统高度逻辑；新版通过反射读取 getMinHeight / getMaxHeight，适配负高度和更高世界上限。
下界传送下界不依赖最高地表点，而是在配置高度范围内扫描候选 Y，降低混合端和不同世界生成器下卡墙概率。
Paper / Purpur运行时检测并优先使用异步传送，旧版本自动回退到同步 Bukkit 传送。
Folia通过反射使用 Global、Region 与 Entity Scheduler；plugin.yml 声明 folia-supported: true。

实际回归环境：Paper 1.8.8、1.12.2、1.16.5、1.21.1、1.26.2，Purpur 1.21.1，Folia 1.20.1，Youer 1.21.1。

从源码构建 ​

压缩包内是 Gradle 项目，已包含 gradlew 与 gradlew.bat。在插件源码目录执行：

powershell
.\gradlew.bat clean shadowJar

构建完成后通常会在 build/libs/ 下生成包含依赖重定位后的 jar。发布部署时优先使用 shadowJar 产物，因为 bStats 已被重定位到插件包内。

部署到服务端 ​

  1. 停止服务端。
  2. 将构建出的 YuRandomTeleport-1.2.0.0-all.jar 放入服务端 plugins/ 目录。
  3. 启动服务端，等待插件生成 plugins/YuRandomTeleport/config.yml 与 lang/zh_CN.yml、lang/en_US.yml。
  4. 在控制台确认出现 YuRandomTeleport 已启用。
  5. 进入游戏执行 /rtp help 或 /yurtp help 检查命令是否注册成功。

首次配置检查 ​

首次上线前至少检查这些配置：

配置默认值建议
world-blacklistlobby将主城、登录服、小游戏大厅等世界加入黑名单。
world-whitelist空列表如果只允许资源世界 RTP，建议改用白名单。白名单非空时会覆盖黑名单。
default.radius.min500控制玩家离出生点或世界坐标中心的最小距离。
default.radius.max2000控制随机范围。大型资源世界可调高。
teleport.wait-seconds5PVP 或生存服建议保留等待时间，防止战斗逃脱。
teleport.cancel-on-movetrue正式服建议保持开启。
cooldown.seconds5生产环境通常建议根据玩法提高到 30 秒、60 秒或更高。
language.defaulten_US服务器默认语言；中文服可设为 zh_CN。
language.use-player-localetrue根据玩家客户端语言选择语言文件，无法识别时回退到默认语言。
default.safety.max-attempts32找不到安全点时可适当增加，但过高会增加瞬时区块加载压力。

接入 Vault 经济 ​

经济功能默认关闭：

yaml
economy:
  enabled: false

启用扣费需要同时满足：

  1. 安装 Vault。
  2. 安装并启用一个 Vault 经济服务提供者。
  3. 将 economy.enabled 改为 true。
  4. 在 default.cost 或 worlds.<世界名>.cost 设置费用。

示例：

yaml
economy:
  enabled: true

default:
  cost: 100.0

worlds:
  resource:
    cost: 50.0
  world_nether:
    cost: 250.0

如果开启经济但没有 Vault，控制台会提示安装 Vault。如果检测到 Vault 但没有经济服务提供者，控制台会提示安装经济插件。

升级已有版本 ​

插件会读取 config-version，当版本落后时合并默认配置并备份旧文件。新版语言位于 lang/；旧版 messages.yml 如果存在，会继续作为 zh_CN 的兼容覆盖层读取。

文件当前版本备份行为
config.yml9更新时生成带旧版本号的 .bak 备份。
lang/zh_CN.yml内置语言首次启动提取；可直接定制。
lang/en_US.yml内置语言首次启动提取；作为缺失消息的最终回退。
messages.yml旧版兼容文件存在时，仅覆盖与内置中文不同的旧自定义项。

升级建议：

  1. 停服备份 plugins/YuRandomTeleport/。
  2. 替换 jar。
  3. 启动一次服务端，让插件自动合并新配置。
  4. 对比备份文件与新文件，确认自定义项仍然保留。
  5. 执行一次 /rtp、一次 /yurtp reload、一次管理员代传送，并按需验证 PAPI/Folia 环境。

卸载 ​

  1. 停止服务端。
  2. 删除 plugins/ 中的 YuRandomTeleport jar。
  3. 如不再需要配置，删除 plugins/YuRandomTeleport/ 目录。

插件不会创建数据库表；经济扣费由 Vault 经济插件处理。
