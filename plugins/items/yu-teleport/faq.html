YuTeleport 常见问题 ​

旧 RTP 短命令还能用吗 ​

最新版源码的主命令是 /yuteleport，默认别名是 /ytp 和 /rtp。文档、权限和 PlaceholderAPI 前缀都已经切换到 yuteleport。如果服务器还有依赖旧随机传送命令的菜单或脚本，建议改为 /ytp 或 /yuteleport。

执行 /rtp 后提示找不到安全传送点 ​

常见原因：

  • teleports.rtp.worlds.default.radius 范围内地形不可用。
  • height.min 和 height.max 限制过窄。
  • allowed-materials 或 allowed-biomes 白名单过于严格。
  • blocked-materials 或 blocked-biomes 覆盖了大量候选点。
  • safety.max-attempts 太低。
  • 下界高度范围没有覆盖可站立洞穴。

排查建议：

  1. 临时开启 debug: true。
  2. 查看控制台拒绝原因。
  3. 放宽白名单或临时清空它。
  4. 提高 max-attempts 到 64 测试。
  5. 针对目标世界单独设置 teleports.rtp.worlds.overrides.<世界名>。

为什么玩家移动后传送取消 ​

这是等待打断机制。默认会按 teleports.defaults.cancel-triggers 处理移动、受伤、交互、聊天和命令。视角转动不会取消，坐标方块变化才按移动处理。

如果希望立即传送：

yaml
teleports:
  defaults:
    warmup-seconds: 0

如果只想给特定玩家跳过等待，给予：

text
yuteleport.bypass.wait

/back 会记录哪些位置 ​

默认会记录三类位置：

  • YuTeleport 成功执行随机传送、warp、home、tpa、坐标分享或 back 前的位置。
  • 玩家死亡位置。
  • 其他插件或服务端命令触发传送前的位置。

相关配置在 teleports.back.capture。如果 /back 提示没有可返回位置，优先检查 teleports.back.enabled、capture.* 开关、include-types、min-distance、expire-seconds，以及玩家是否拥有 yuteleport.back.use 和访问死亡点所需的 yuteleport.back.death。

/back list 可查看可用历史；交互式聊天开启时，点击列表项会执行 /back <UUID> 返回指定条目。persist: true 时历史会保存在 plugins/YuTeleport/data/back/。

开启经济后没有扣费 ​

请按顺序检查：

  1. economy.enabled 是否为 true。
  2. economy.provider 是否与已安装插件一致，vault 需要 Vault 和经济插件，playerpoints 需要 PlayerPoints。
  3. 对应模块的 cost 是否大于 0。
  4. 命令执行者或付款方是否拥有 yuteleport.bypass.cost。
  5. 控制台是否提示经济服务未挂钩或扣费失败。

扣费通常在目的地确认后进行。等待被取消、找不到安全点或事件取消时不会产生最终扣费，已扣款路径会按插件逻辑退款。

控制台能不能执行 /rtp ​

控制台不能执行无参数 /rtp、/ytp 或 /yuteleport，因为控制台没有当前世界和玩家位置。

控制台可以执行：

text
yuteleport <玩家>
yuteleport <玩家> <世界>
yuteleport reload

白名单和黑名单同时配置时谁优先 ​

白名单优先。只要 whitelist 非空，插件就只允许白名单内世界传送，blacklist 会被忽略。

示例：

yaml
world-access:
  blacklist:
    - lobby
  whitelist:
    - resource

此时只有 resource 允许传送。

玩家有权限但仍无法代传送其他人 ​

代传送需要满足两个条件：

  1. 命令执行者拥有 yuteleport.teleport.others。
  2. 目标玩家拥有 yuteleport.use。

如果目标玩家没有 yuteleport.use，插件会返回权限不足。若目标玩家在冷却中，命令执行者需要 yuteleport.bypass.cooldown.others 或目标玩家拥有 yuteleport.bypass.cooldown。

warp 或 home 数量权限不生效 ​

确认权限节点写法：

text
yuteleport.warp.limit.25
yuteleport.home.limit.25
yuteleport.warp.limit.unlimited
yuteleport.home.limit.unlimited

如果权限过期后数量超额，已有数据会保留，但超额项可能暂时不可用，玩家可删除或重新获得更高上限权限。

PlaceholderAPI 变量没有值 ​

依次确认：

  1. PlaceholderAPI 已安装并启用。
  2. integrations.placeholderapi.enabled 为 true。
  3. 安装或替换 PlaceholderAPI 后重启过服务器，或执行过 /yuteleport reload。
  4. 变量前缀是 %yuteleport_*%，不是旧随机传送插件前缀。

测试：

text
/papi parse me %yuteleport_status%
/papi parse me %yuteleport_version%

位置类变量在玩家尚无传送快照时返回空字符串，这是正常行为；未知变量返回 null。

修改配置后需要重启吗 ​

大多数配置可以通过以下命令重载：

text
/yuteleport reload

重载会重新读取配置、语言文件、世界规则、经济挂钩、PlaceholderAPI 注册和模块命令。替换 jar、安装新依赖、修改服务端核心或排查模块命令注册问题时，建议重启服务器。

Folia 上需要额外配置吗 ​

不需要。插件声明 folia-supported: true，会在运行时检测 Folia 并使用 Global、Region 和 Entity Scheduler。其他插件通过 Java API 的 future 回调或事件操作实体、区块时，仍应按 Folia 规则调度到对应实体或区域。

bStats 可以关闭吗 ​

可以在服务器的 bStats 配置中关闭。关闭后不会影响随机传送、warp、home、tpa、back、坐标分享、冷却、扣费或世界规则。
